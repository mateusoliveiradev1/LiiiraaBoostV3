## 3. Visual North Star — Cobalt Ignition Bay

**Named north star:** **Cobalt Ignition Bay**.

The scene is the exact moment a high-performance Windows machine comes alive before a competitive session. The room remains dark and disciplined, but the product is no longer visually dormant: one electric cobalt signal ignites the primary action, traces the active task, and gives the real desktop artifact staged presence. The composition feels engineered, energized, and assured—not quiet to the point of anonymity.

Three physical brand words: **electrified, engineered, assured**.

The public surface communicates. Account and admin serve tasks. They share the same signature, material vocabulary, type discipline, and status language, but do not reuse one layout.

### Non-negotiable character

- Near-black blue-neutral canvas, layered graphite/ink-blue surfaces, electric cobalt signature, and a small cyan highlight.
- High-contrast type with clear size jumps; no tiny typography spread across large canvases.
- One visual focal point per viewport: product artifact on public, active task workspace on account/admin.
- Familiar application patterns with authored finish: substantial topbar, persistent desktop rail, active current task, elevated focal workspace, contextual side panel, and dense semantic rows/tables.
- Light and glow explain focus and energy. They never become decorative RGB ambience.
- Beauty comes from hierarchy, proportion, type, material, and authored content—not effects piled onto wireframes.

### Absolute visual bans

No gradient text, decorative grid backgrounds, glassmorphism, rainbow/RGB lighting, neon green, giant metric tiles, identical or nested card walls, rounded rectangles around every paragraph, stock dashboard templates, ornamental gamer motifs, fake terminal styling, fake benchmark numbers, urgency, affiliate content, or cinematic effects that obscure work.

## 6. Spacing, Grid, Radius, Shadow, and Glow

### Spacing scale

All values are multiples of four. No arbitrary local values.

| Token | Value | Usage |
|---|---:|---|
| `space-1` | 4px | Icon/label micro-gap |
| `space-2` | 8px | Compact inline gap |
| `space-3` | 16px | Default control/content gap; mobile edge |
| `space-4` | 24px | Panel padding; compact section gap |
| `space-5` | 32px | Workspace gap; desktop panel padding |
| `space-6` | 48px | Page intro and mobile chapter gap |
| `space-7` | 64px | Public hero grouping; major product break |

These seven values are the complete spacing-token set. Public cinematic rhythm comes from composition, not extra tokens: alternate 64px and 48px section padding, use 32px internal group gaps, and create larger perceived pauses by pairing a 64px section edge with a distinct tonal transition. Account/admin use 16/24/32/48 only. Pointer targets remain at least 44×44px.

### Grid

- Public: 12 columns, max content width 1280px, 24px gutters at ≥960px, 16px at <960px.
- Account: 264px desktop rail plus fluid workspace; workspace max 1240px and centered inside remaining width.
- Admin: 280px desktop rail plus fluid workspace; workspace max 1320px.
- Standard product content grids: 8/4 or 7/5. A single form never stretches beyond 560px; pair it with a contextual summary or use the remaining width for useful task content.
- No main task region may leave more than 25% of the available desktop workspace as unexplained empty canvas above the fold.

### Radius

| Token | Value | Use |
|---|---:|---|
| `radius-control` | 6px | Buttons, fields, compact selection |
| `radius-panel` | 10px | Product panels, menus, task workspaces |
| `radius-stage` | 14px | Hero product frame, dialog, sheet only |
| `radius-pill` | 999px | Short status/channel chips only |

No nested panel repeats the same rounded rectangle more than two levels deep.

### Elevation and material vocabulary

| Level | Material | Contract |
|---|---|---|
| E0 | Canvas | Flat near-black page field; no shadow |
| E1 | Workspace/panel | Tonal step plus optional 1px outer boundary; no large shadow |
| E2 | Focal/raised panel | Tonal step plus one 1px highlight edge and **no shadow**; at most one permanent E2 focal region per viewport |
| E3 | Overlay | `0 24px 64px rgb(0 0 0 / 52%)`; dialogs, menus, command/search only |

Thin dividers may separate rows inside a semantic table/list. They may not form the entire page into a spreadsheet-like grid. Prefer tonal groups, spacing, headings, and one outer boundary.

### Glow limits

- Hero bloom: one radial cobalt-to-cyan bloom behind the real product artifact, maximum 520×360px visible footprint, maximum 20% peak opacity, blur 64px.
- Action/selection glow: maximum `0 0 24px` at 14% accent opacity; only primary CTA or current selection, never both in the same local group.
- Maximum two glowing elements visible in one viewport.
- No glow on body copy, semantic warnings, ordinary cards, every button, or inactive navigation.
- Forced colors removes glow. Reduced motion disables animated glow. Glow cannot carry state or focus alone.

## 8. Color Contract

Use OKLCH as the canonical source, with generated sRGB fallbacks. Final token implementation must pass automated contrast checks.

| Role/token | OKLCH | Usage |
|---|---|---|
| Dominant canvas 60% `--lb-canvas` | `oklch(0.115 0.018 260)` | Page canvas and uninterrupted outer field |
| Canvas inset `--lb-canvas-inset` | `oklch(0.145 0.024 260)` | Recessed navigation and stage interior |
| Secondary panel 30% `--lb-panel` | `oklch(0.180 0.032 258)` | Sidebars, product panels, rows, section bands |
| Raised panel `--lb-panel-raised` | `oklch(0.225 0.045 257)` | Focal workspace and overlays |
| Electric cobalt 10% `--lb-accent-electric` | `oklch(0.670 0.210 255)` | Primary CTA, active task, committed selection, product-stage edge |
| Electric cobalt hover `--lb-accent-electric-hover` | `oklch(0.730 0.190 250)` | Primary CTA hover only |
| Electric cobalt pressed `--lb-accent-electric-pressed` | `oklch(0.610 0.200 255)` | Primary CTA pressed only |
| Cyan edge `--lb-accent-cyan` | `oklch(0.820 0.135 220)` | Focus ring, small highlight, artifact edge; never a second CTA color |
| Primary text | `oklch(0.965 0.012 255)` | H1, headings, critical values |
| Secondary text | `oklch(0.760 0.030 255)` | Body and explanations |
| Tertiary text | `oklch(0.650 0.028 255)` | Non-action metadata only |
| Subtle line | `oklch(0.285 0.035 255)` | Outer boundaries and row separation |
| Strong line | `oklch(0.390 0.060 255)` | Control boundary and focus-adjacent structure |

The 60/30/10 ratio applies to solid surface area. A low-opacity hero bloom does not authorize additional blue panels. The signature is stronger than before but remains directed.

Accent is reserved for:

1. the single primary CTA in a decision region;
2. current route/task selection;
3. keyboard focus via cyan edge plus system fallback;
4. committed progress or verified selection;
5. the real-product stage edge and its one bounded bloom.

Accent is not used for all links, inactive icons, every panel border, ordinary positive states, or decorative text.

### Primary CTA contrast pairs

The electric cobalt fill never uses white text. Its label is the dark canvas token so normal-size CTA text remains at least 4.5:1.

| State | Background | Label/boundary | Required test |
|---|---|---|---|
| Default/loading | `--lb-accent-electric` | `--lb-canvas`; loading preserves the same pair and button width | computed contrast ≥4.5:1 |
| Hover | `--lb-accent-electric-hover` | `--lb-canvas` | computed contrast ≥4.5:1 |
| Pressed | `--lb-accent-electric-pressed` | `--lb-canvas` | computed contrast ≥4.5:1; no scale animation |
| Disabled | `--lb-canvas-inset` | `--lb-text-secondary` plus `--lb-strong-line` boundary | computed contrast ≥4.5:1; state is not expressed by opacity alone |
| Forced colors | system `ButtonFace` | system `ButtonText` plus 1px `ButtonText` boundary; focus uses `Highlight` | browser forced-colors assertion; authored fill/glow removed |

Automated token tests must evaluate every pair in sRGB after OKLCH conversion. A color adjustment that drops any pair below 4.5:1 blocks the build.

### Semantic colors

| Semantic role | OKLCH | Companion |
|---|---|---|
| Success/verified | `oklch(0.750 0.170 150)` | check icon/pattern + explicit label |
| Warning | `oklch(0.820 0.160 82)` | warning icon/pattern + consequence |
| Critical | `oklch(0.700 0.200 25)` | critical icon/pattern + blocking reason |
| Destructive | `oklch(0.580 0.220 25)` | destructive action only |
| Preview/info | cyan text on raised neutral surface | info icon + “Preview”/“Prévia” label |
| Unavailable | neutral raised surface and secondary text | unavailable icon + reason |

Experimental/preview state must not use purple in ordinary chrome. Color never communicates status alone. Forced colors maps canvas/text/boundaries/focus to system colors.

## 9. Public Shell and Cinematic Product Hero

### Public topbar

- Height: 72px at ≥960px; 60px below 960px.
- Content max width: 1280px; horizontal padding 24px desktop, 16px mobile.
- Left: full Liiiraa Boost lockup, never boxed initials.
- Center: six intent pillars at ≥1100px: Product, Evidence, Compatibility, Plans, Documentation, Download/Releases. Exactly one uses `aria-current="page"` and the committed selected state.
- Right: search, route-preserving flag-plus-language control, and one compact primary CTA.

- Locale control always shows flag + localized language text (`🇧🇷 Português`, `🇺🇸 English`) and an explicit accessible language name. It preserves the current canonical route; unmatched state fails safely to the target-locale Home.

### Hero proportions

At ≥1280px:

- Hero uses a centered 12-column composition, `min-height: calc(100svh - 72px)`, maximum 920px.
- Promise group spans columns 3–11, max width 940px, center aligned. H1 begins 64px below the header.
- H1 uses the exact approved promise: **“Prepare seu PC. Prove o resultado. Restaure com controle.”** / **“Prepare your PC. Prove the result. Restore with control.”**
- Lead is one paragraph, max 58ch, placed 24px below H1.
- CTA pair sits 32px below the lead. Primary is solid electric cobalt; secondary is a quiet outlined action. The two must not have equal visual weight.
- Product stage spans columns 2–12, max width 1120px, aspect ratio 16:9, centered. Its top edge must appear no lower than 560px from the page top in the 1440×900 golden, leaving at least 260px of the real product visible above the fold.
- The actual desktop screenshot occupies at least 88% of the stage area. It cannot appear as a small card floating in a large empty page.
- One cobalt/cyan bloom sits behind the lower center of the artifact. No decorative grid, fake window chrome, or invented telemetry is added.

At 960–1279px, keep the centered hierarchy; product stage uses `calc(100vw - 48px)`. Below 960px, remove the hero height floor, use 48px top/bottom padding, keep copy and primary CTA first, then a responsive 16:10 product crop and a visible full-screenshot action. At 390px the CTA pair stacks and each target is 48px high.

### Product stage truth

- Source only from the deterministic real desktop capture pipeline.
- Do not edit screenshot values, text, state, provenance, or interface geometry.
- Show one concise caption: product version + “real deterministic capture.” Place scenario, viewport, commit, checksum, and full provenance in a native `details` disclosure below the stage.
- The evidence disclosure must not compete with the H1, CTA, or product artifact.
- Provide `View complete screenshot` / `Ver captura completa` adjacent to the disclosure.

### Public section rhythm

The Home uses five authored movements, not a document outline and not a card wall:

1. **Ignition Hero** — promise, CTA pair, real product stage.
2. **Prepare / Prove / Restore band** — three connected steps in one horizontal sequence at wide widths; not three floating cards.
3. **Evidence in context** — one large annotated product crop paired with a concise proof explanation and contextual disclosure.
4. **Compatibility decision** — authored decision composition with supported/under-validation/unavailable states and one primary compatibility action.
5. **Release boundary** — elevated but quiet fail-closed availability panel with release-state action; no alarming debug language.

Later public routes vary composition among split editorial bands, full-width evidence tables, timelines, product crops, and decision panels. No route repeats identical card geometry three sections in a row.

Ordinary visitor copy never leads with architecture, fixtures, manifests, build IDs, phase numbers, authority adapters, or implementation policy. That detail remains available where materially relevant.

## 14. Interaction and Navigation Contracts

- Every route has one visible H1 and one `main`; focus moves to the H1 after client route navigation.
- Public, account, and admin use active/task-oriented navigation with exactly one current destination.
- Locale controls preserve canonical route identity. Admin also preserves only a validated role. Flags are decorative companions, never the sole language name.
- Browser Back/Forward reproduces URL-addressable public search, filters, pagination, version, and channel state.
- Cross-origin links identify destination/boundary and transfer only allowlisted safe context. Never transfer session, consent, diagnostic, form, or credential data through URLs.
- Overlays restore focus to the invoker. Mobile disclosures use native or React Aria semantics and remain operable with keyboard, touch, and screen reader.
- No interaction depends exclusively on hover. No dead link, `#`, generic coming-soon page, or hidden automatic redirect is allowed.

### Release and authority boundaries

- Stable remains default; Beta requires explicit opt-in; Experimental remains separate.
- Artifact, signature, hash, publisher, manifest, compatibility, or approval mismatch blocks download with no bypass.
- Until a publicly trusted artifact is approved, the primary CTA remains `Check compatibility`; the release route ends in `DownloadAvailabilityGate`.
- Account/admin actions follow `input → validation → review → proportional confirmation → disconnected authority → no-change receipt`.
- Ordinary task screens use quiet preview status. Sensitive review and receipt screens state exact consequence, reviewed object, future authority, and `remoteStateChanged: false` in human language.

Release-blocking across all surfaces:
