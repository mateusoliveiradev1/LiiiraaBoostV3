# Phase 3 — UI Design Contract

Visual and interaction contract for the complete Liiiraa Boost web ecosystem. Generated by `gsd-ui-researcher`; the checker upgrades `status` after verification.

This contract covers three independently deployable Next.js surfaces:

1. the public, documentation, compatibility, release, and download application;
2. the account and support-preview application;
3. the isolated administrative application.

The surfaces share visual tokens, status language, evidence rules, localization, and accessibility behavior. They do not share shells, session authority, sensitive state, origins, cookies, CSP, or deployment policy merely to create visual continuity.

### shadcn gate

No `components.json` exists. The project stack explicitly prohibits shadcn/ui, dashboard templates, and third-party registry blocks because they conflict with the bespoke product identity. The gate is therefore resolved as **manual design system**, not left undecided.

### Visual register by surface

- **Public Home:** brand register. More cinematic, asymmetric, and spacious, but still evidence-led and fast.
- **Documentation, compatibility, releases:** hybrid register. Brand confidence in entry points; product density in technical content.
- **Account:** product register. Clear, approachable, responsibility-led, and calm.
- **Admin:** product register. Dense, operational, role-specific, and restrained.

No surface may use RGB, neon, glassmorphism, gradient text, decorative grids, repeated icon-card walls, giant metric tiles, oversized radii, ornamental gamer motifs, testimonial fabrication, or stock dashboard composition.

## 3. Spacing Scale

Declared values are inherited unchanged from `packages/design-tokens`:

| Token | Value | Usage |
|---|---:|---|
| `space-1` | 4px | Icon/label gap, inline metadata separation |
| `space-2` | 8px | Compact control internals, dense row gaps |
| `space-3` | 16px | Default control and content spacing |
| `space-4` | 24px | Section padding, comfortable row groups |
| `space-5` | 32px | Layout gaps, compact chapter breaks |
| `space-6` | 48px | Major section breaks |
| `space-7` | 64px | Page/chapter separation |

Rules:

- Spacing values outside this scale are forbidden.
- Public Home varies rhythm by combining `24/48/64`; it must not repeat an identical section cadence.
- Account and admin use `16/24/32`; compact density changes whitespace, not type size or target size.
- The only size exception is the accessibility target: every pointer target is at least **44×44px**.
- Working surfaces use the existing 6px radius; temporary overlays use 10px. Pills are reserved for tags, channels, and compact status labels.
- Permanent sections are separated by tone, spacing, or one divider. They do not combine thin borders with wide soft shadows.

## 4. Typography

The existing four-size and two-weight contract remains canonical.

| Role | Family | Size | Weight | Line height | Usage |
|---|---|---:|---:|---:|---|
| Label | Manrope | 13px | 600 | 18px | Navigation, controls, metadata labels |
| Body | Manrope | 15px | 400 | 24px | Explanations, policy summaries, document prose |
| Heading | Manrope | 20px | 600 | 26px | Section and workspace headings |
| Display | Manrope | 28px | 600 | 34px | Hero promise and page-defining statements only |

Data uses JetBrains Mono at the existing label/body sizes:

- compact data: 13px/20px, 400 or 600;
- body data: 15px/24px, 400 or 600.

Rules:

- Exactly two weights exist: 400 and 600.
- Human language uses Manrope. Hashes, versions, identifiers, timestamps, error codes, manifest fields, and tabular numbers use JetBrains Mono.
- Mono is never used for prose or as decorative “technical” styling.
- Public hero display is capped at 18 characters per line where language permits and never exceeds 16ch measure. Scale comes from composition and the real product artifact, not a fifth text size.
- Body copy is capped at 65–75ch. Documentation’s primary reading column is 68ch.
- Headings use `text-wrap: balance`; paragraphs use `text-wrap: pretty`.
- Sentence case is the default. All-caps is restricted to literal confirmation phrases and stable technical identifiers.
- No tiny tracked eyebrow precedes every section. A label appears only when it conveys channel, version, provenance, or state.

## 5. Color

The screen-level distribution is restrained: 60% dominant, 30% secondary structure, no more than 10% cobalt.

| Role | Value | Usage |
|---|---|---|
| Dominant (60%) | `#090B0F` | Page canvas, long-form background, uninterrupted reading field |
| Inset dominant | `#0B0E13` | Code, technical detail, recessed navigation |
| Secondary (30%) | `#121722` | Header, side navigation, work regions, rows |
| Raised secondary | `#181F2C` | Dialogs, popovers, active inspectors only |
| Accent (≤10%) | `#315ACD` | One primary CTA, active selection, committed progress |
| Accent signal | `#7EA0FF` | Focused links, focus-adjacent signal, selected evidence reference |
| Primary text | `#F4F7FB` | Headings, critical values, primary copy |
| Secondary text | `#AAB4C4` | Body metadata and explanations |
| Tertiary text | `#7D899B` | Nonessential metadata only; never form hints or actionable text |
| Destructive | `#B52D3A` | Destructive confirmation action only |

Accent is reserved for:

1. the single primary action in the current decision region;
2. active navigation/selection;
3. visible keyboard focus support;
4. verified selection or committed progress;
5. a small focal edge or crop guide around the real product artifact.

Accent is not used for ambient gradients, every link, decorative glows, large background washes, or ordinary positive states.

Semantic colors remain independent of brand meaning:

| Semantic role | Value | Required companion |
|---|---|---|
| Success / verified | `#4DCA8B` | Icon/pattern plus explicit label |
| Warning | `#F3B64A` | Icon/pattern plus consequence text |
| Critical / integrity failure | `#FF747D` | Icon/pattern plus blocking reason |
| Experimental | `#C08CFF` | “Experimental” label plus policy |
| Unavailable / disabled | `#3D4452` fill | “Unavailable” label plus reason |

Every text/background pairing must pass WCAG 2.2 AA. Body copy and placeholders require 4.5:1; large text and non-text UI boundaries require 3:1. Forced-colors mode replaces authored colors with system colors without removing boundaries or status labels.

## 6. Image and Atmospheric Direction

The physical scene is a serious PC in the quiet moments before a competitive session: near-black equipment, controlled instrument light, and a real optimizer interface ready for inspection.

### Home hero

- Use a 5/7 asymmetric composition at wide viewports: promise and CTA occupy the narrower runway; the real desktop screenshot is the dominant artifact.
- The approved PT-BR promise is **“Prepare seu PC. Prove o resultado. Restaure com controle.”**
- English counterpart: **“Prepare your PC. Prove the result. Restore with control.”**
- The screenshot must come from the deterministic desktop capture pipeline and retain version, locale, scenario, viewport, and provenance metadata.
- Cropping or framing may emphasize the product, but values, labels, state, and provenance inside the capture may not be altered.
- Atmospheric imagery is supporting material only. It may not imitate an application, imply unbuilt hardware detection, or compete with the real product.
- No generic headset, cyber-city, RGB desk, synthetic benchmark, fake telemetry, or generated product mockup may ship.

### Evidence Stage

Immediately after the hero, show an evidence-led product stage rather than a repeated feature-card row:

1. what the product can prove;
2. how compatibility is established;
3. how recovery remains available;
4. where a claim’s source, scope, version, and validation state can be inspected.

Use authored rows, annotated product crops, timelines, and evidence disclosures. Do not turn each concept into an identical floating card.

### Delivery

- Navigation, promise, compatibility CTA, and critical notices render before hero media.
- Above-the-fold screenshots use responsive AVIF/WebP with explicit dimensions and a non-deceptive fallback.
- Below-the-fold media is lazy-loaded.
- No essential action or understanding depends on video, animation, or high-bandwidth imagery.
- The full unmodified screenshot is always available from a visible “View complete screenshot” action.

Primary navigation pillars, in this order:

1. Product
2. Evidence
3. Compatibility
4. Plans
5. Documentation
6. Download / Releases

### Account shell

Navigation is organized by responsibility:

1. Overview
2. Profile
3. Security
4. Subscription and invoices
5. Device
6. Downloads
7. Privacy
8. Support

A persistent global preview boundary appears below the shell header. The boundary is repeated inside every sensitive review and receipt.

### Admin shell

The admin application has a separate origin and no ordinary link from public or account navigation. Its role-specific navigation exposes only applicable areas:

- Support;
- Operations;
- Security;
- Audit.

Role identity and preview provenance are persistent. The shell never presents one omnipotent “admin” view.

### Route manifest

One typed canonical route manifest must own path, locale behavior, surface, shell, title, indexing, security boundary, required scenario, and contextual-link identity. Navigation, breadcrumbs, sitemap, redirects, desktop deep links, and route tests are generated or validated against it.

Minimum route families:

| Surface | Required families |

| Public | Home, Product, Evidence, Compatibility, Plans, Search, Support, Status, Policies, Responsible Disclosure |
| Documentation | Task index, versioned article, technical reference, troubleshooting, historical/stale article |
| Releases | Release index, channel, version notes, manifest/integrity, download gate, installation verification |
| Account | Sign-in preview, Overview, Profile, Security, Subscription/Invoices, Device, Downloads, Privacy, Support |
| Admin | Role landing, Support case, Operations review, Security review, Consent-scoped diagnostics, Audit event/timeline |

Dead controls, `#` links, generic “coming soon” pages, automatic failure-hiding redirects, and routes absent from the canonical manifest are forbidden.

## 9. Interaction Contracts

### Navigation and boundary changes

- Every route has one visible H1 and focuses it after client-side navigation.
- Focus returns to the invoking control when overlays close.
- Locale, documentation version, release channel, requested destination, and safe return path survive eligible transitions.
- Before crossing to another origin, identify the destination and security-boundary change. Do not transfer session, diagnostic, or sensitive form state through query parameters.
- Browser Back/Forward reproduces URL-addressable search, filters, pagination, version, and channel state.

### Public search

- Search covers product content, capability identifiers, compatibility, plans, documentation, releases, support, and error codes.
- Results expose content type, locale, applicable version, availability, and validation state.
- Filters are URL-backed and keyboard operable.
- Search submits explicitly; suggestions never replace the submitted query without confirmation.
- No-result state preserves query and filters and offers compatible next paths.
- Private account/admin content, internal preview scenarios, and non-indexable content never enter public results.

### Documentation

- Entry pages are task-led: getting started, preparing, measuring, optimizing, restoring, troubleshooting.
- Every article begins with purpose and next safe action, then evidence, risk, compatibility, recovery, and deeper detail.
- Version and release channel remain visible while reading.
- A historical or unsupported article shows a persistent notice and canonical current alternative. It is never silently redirected.
- Contextual desktop links open the exact locale/version/section where available. If unavailable, show the mismatch and a safe compatible choice.
- Code and technical identifiers may scroll on one axis; ordinary prose and navigation may not.
- Troubleshooting begins with observed state/error code and ends in verified recovery or escalation.
- Documentation may explain verification, but must not distribute generic mutation scripts, registry recipes, or PowerShell execution channels.

### Compatibility, plans, and evidence

- Compatibility asks only information needed for a defensible result and labels user-provided answers.
- Support states are exact: Available, Demonstrative preview, Under validation, Planned, Unsupported, Unavailable.
- Every material claim exposes source, provenance, scope, applicable version, validation state, and what remains unproven.
- Plans disclose price, billing period, renewal, taxes, cancellation, refund terms, device rules, and expiration effects before any simulated confirmation.
- No discount countdown, pressure, fear, hidden renewal term, safety paywall, synthetic score, or invented gain is allowed.

### Releases and download

1. Stable is selected by default.
2. Beta requires explicit opt-in and shows audience, risk, support, and update policy.
3. Experimental is visually and structurally separate.
4. User reviews version, architecture, Windows lifecycle, compatibility evidence, publisher, size, SHA-256, signature state, provenance, and canonical manifest.
5. Signature, hash, publisher, artifact, or manifest disagreement blocks the flow completely.
6. Until a publicly trusted artifact is approved, the full journey ends at `DownloadAvailabilityGate`; no development/self-signed artifact and no “continue anyway” path is exposed.
7. Once approved, the CTA may change from “Check compatibility” to “Check compatibility and download.”
8. After an approved download, show independent Authenticode and hash verification, safe installation, expected warnings, cancellation guidance, and support.

Stable download does not require an account. Download analytics remain aggregate, minimal, purpose-bound, and unbound from a PC identity.

### Account preview workflow

Every Phase 4-dependent action follows:

`input → validation → review → proportional confirmation → authority boundary → no-change receipt`

The interface must:

- keep a global “deterministic preview” rail visible;
- repeat the preview boundary at sensitive actions;
- validate email, social, passkey, MFA, session, billing, device, privacy, and support forms as their real successors will;
- never invent a session, payment, invoice, device change, support upload, privacy request, or security-method mutation;
- name the future authority in the receipt and state that no remote state changed;
- preserve entered safe work through retryable failures where privacy permits.

### Admin preview workflow

- Role and allowed scope are visible in the shell and action review.
- Diagnostic access is blocked without explicit, scoped, time-limited consent.
- Consent review names purpose, permitted fields, expiration, requesting actor, and resulting immutable audit event.
- Critical actions require purpose, impact review, simulated reauthentication, and object-specific confirmation.
- Every action ends with a no-change receipt until Phase 4 authority exists.
- Audit history is an immutable, correlatable timeline with actor, role, action, redacted target, reason, consent, timestamp, result, and correlation identifier.
- On viewports below 960px, safe review, alert triage, case reading, audit inspection, and support responses remain available; high-risk administration is blocked with a clear desktop-class viewport requirement.

## 10. State Contract

Every applicable route must have authored compositions for:

- initial loading and delayed loading;
- success/ready;
- empty;
- validation error;
- recoverable request failure;
- partial outage;
- offline;
- stale data;
- expired session;
- permission denied / role restricted;
- unsupported;
- unavailable authority;
- simulated preview;
- destructive review;
- cancellation;
- no-change receipt;
- 404, 403, 410, and 500.

State rules:

- Skeletons match final structure and never imply data exists.
- Indeterminate progress does not show a fabricated percentage.
- Empty states explain why the region is empty and name one safe next action.
- Errors state the affected capability, what remains safe, and the next recovery path.
- Partial outages keep public content and documentation available where safe; account/admin block ambiguous actions and preserve valid local work.
- Expired sessions preserve non-sensitive form work only when explicitly safe, then route through the sign-in preview boundary.
- 404, 403, 410, and 500 are distinct. Each preserves locale, redacts diagnostics, and offers relevant destinations without masking the failure.
- Status is never communicated by color alone.

### Provenance labels

| Canonical kind | PT-BR | English |
|---|---|---|
| `measured` | Medido | Measured |
| `simulated` | Prévia simulada | Simulated preview |
| `derived` | Derivado | Derived |
| `user-provided` | Informado pelo usuário | User-provided |
| `unavailable` | Indisponível | Unavailable |

Validation state is separate from provenance. A simulated value cannot be styled as authoritative merely because it is schema-valid.

## 11. Copywriting Contract

PT-BR is the default authoring locale; English receives equivalent human review.

| Element | PT-BR | English |
|---|---|---|
| Hero promise | Prepare seu PC. Prove o resultado. Restaure com controle. | Prepare your PC. Prove the result. Restore with control. |
| Primary CTA while distribution is gated | Verificar compatibilidade | Check compatibility |
| Primary CTA after public artifact approval | Verificar compatibilidade e baixar | Check compatibility and download |
| Preview boundary | Prévia determinística — nenhuma autoridade remota está conectada. | Deterministic preview — no remote authority is connected. |
| Generic empty heading | Nada requer sua atenção | Nothing needs your attention |
| Generic empty body | Quando houver dados confiáveis ou uma ação disponível, eles aparecerão aqui com a origem indicada. | Trusted data or an available action will appear here with its source identified. |
| Search empty heading | Nenhum resultado confiável | No trusted results |
| Search empty body | Revise os termos ou remova um filtro. A busca não mostra conteúdo privado nem versões incompatíveis sem aviso. | Revise the query or remove a filter. Search does not expose private content or incompatible versions without notice. |
| Recoverable error | Não foi possível carregar esta parte. O restante permanece disponível; tente novamente ou consulte o status do serviço. | This part could not be loaded. The rest remains available; try again or check service status. |
| Download gate heading | Download público ainda não disponível | Public download is not available yet |

| Integrity failure | A verificação de integridade não corresponde ao manifesto oficial. O download foi bloqueado. | Integrity verification does not match the official manifest. The download is blocked. |

Copy rules:

- Sell through proof, compatibility, reversibility, and control.
- Material claims require evidence, scope, state, version, and bilingual review.
- Never use miracle language, urgency, fear, invented gains, fake issue counts, “one click,” “boost now,” or “continue anyway.”
- Button labels use a specific verb plus object.
- Form errors identify the field and correction; an error summary links to each invalid field.
- Dates, times, numbers, sizes, prices, taxes, percentages, and durations use locale-aware formatters.
- Technical identifiers remain stable while their accessible descriptions are localized.

### Destructive and sensitive actions

All actions below are previews in Phase 3 and must end in the no-change receipt.

| Action | Confirmation contract |
|---|---|
| Revoke device | Show affected device, cooldown/entitlement consequence, simulated reauthentication, then `Revogar dispositivo` / `Revoke device` |
| Revoke session | Show session, last activity, current-session impact, then `Revogar sessão` / `Revoke session` |
| Request account deletion | Show retention, cancellation, recovery window, and unavailable Phase 4 authority; require explicit object-specific confirmation |
| Submit privacy export/correction/deletion | Show purpose, scope, retention, sharing, revocation, and future authority before confirmation |
| Submit support data | Preview every included field, allow redaction/removal, state retention and sharing, then collect explicit consent |
| Critical admin action | Require purpose, impact review, simulated reauthentication, role/scope review, object-specific confirmation, and audit-event preview |

Typed phrases are reserved for irreversible/high-impact previews and must be displayed in full in the active locale. Generic “Are you sure?” dialogs are forbidden.

## 12. Responsive Layout Contract

| Range | Contract |
|---|---|
| `<640px` | Single-column mobile; 16px screen padding; full-screen public menu; essential table columns plus row detail |
| `640–959px` | Compact tablet; 16px padding; two-column layouts only where reading order remains obvious |
| `960–1279px` | Desktop-class; 24px padding; public asymmetric hero; account/admin persistent navigation; admin high-risk controls may appear |
| `≥1280px` | Wide layout; 24px padding; full documentation index/content/context composition; capped content measures |

Rules:

- Public mobile order is hero promise → compatibility CTA → trust boundary → responsive product crop → full screenshot action.
- The mobile menu preserves every navigation pillar, search, locale, and an unobtrusive primary CTA.
- Documentation uses a collapsible index and version controls below 960px; article depth is not removed.
- Compatibility, account, and admin tables show essential columns first and expose complete row detail through an explicit disclosure. They do not become card walls.
- Ordinary use must not require horizontal scrolling. One-axis scrolling is allowed only for code, hashes, manifests, and truly tabular technical data.
- Account mobile uses one responsibility at a time; it does not compress the desktop sidebar into icon-only ambiguity.
- Admin mobile retains safe review work but blocks high-risk execution below 960px.
- The ecosystem must reflow at 400% browser zoom and 200% text scaling without clipping, overlap, or two-dimensional scrolling.
- No information or action depends exclusively on hover.

## 13. Motion Contract

| Motion | Duration | Easing |
|---|---:|---|
| Hover/focus color | 100ms | linear |
| Control/row state | 140ms | `cubic-bezier(0.2, 0, 0, 1)` |
| Inspector/popover | 180ms | `cubic-bezier(0.2, 0, 0, 1)` |
| Route transition | 220ms | `cubic-bezier(0.2, 0, 0, 1)` |
| Progress state | 240ms | `cubic-bezier(0.2, 0, 0, 1)` |

Rules:

- Route translation is at most 8px.
- Home may use one purposeful artifact reveal, but content is visible by default and remains usable if animation never runs.
- No bounce, elastic motion, count-up metric, parallax dependency, scan line, particle field, decorative telemetry animation, or infinite ambient loop.
- Layout properties are not animated when transform, opacity, mask, or tonal change can preserve continuity.
- `prefers-reduced-motion` removes translation, scale, stagger, count-up, and interpolation; essential state changes use immediate or ≤100ms opacity transitions.
- Motion never delays navigation, compatibility, CTA, error, or consent information.

## 14. Accessibility Contract

Release-blocking requirements across all three surfaces:

- WCAG 2.2 AA, including 2.4.11 Focus Not Obscured and 2.5.8 Target Size.
- One `main` landmark and one visible H1 per route; named navigation and complementary regions.
- A visible-on-focus skip link precedes each shell.
- Tab order follows visual reading order; positive `tabindex` is forbidden.
- Menus, tabs, listboxes, disclosures, dialogs, and comboboxes use React Aria keyboard/focus behavior.
- Focus is never hidden by sticky headers, consent rails, or preview rails.
- Dialogs trap focus; nonmodal inspectors do not claim modal semantics.
- Required information never lives only in a tooltip.
- Forms associate labels, descriptions, errors, and error summaries programmatically.
- Status changes use polite live regions; assertive announcements are reserved for immediate safety/integrity blocking.
- Tables have captions, header associations, and keyboard-accessible row details.
- Charts or evidence graphics require a text summary and data-table alternative.
- Visible focus, selected state, status, and boundaries survive Windows High Contrast/forced colors.
- Every action remains operable at 400% zoom, 200% text scaling, reduced motion, keyboard-only input, touch, and screen reader.
- PT-BR, English, and a 35%-expanded pseudo-locale must not clip product-critical copy.

## 15. Privacy, Trust, and Publication

- Do not show a cookie banner when only strictly necessary storage is used.
- Optional measurement requires prior, granular, reversible consent.
- Every data-collection point states purpose, required fields, retention, sharing, revocation, and a link to the full policy.
- Privacy, Terms, and Security documents provide plain-language summary, full text, effective date, history, and accountable contact.
- Responsible Disclosure states secure reporting channel, scope, prohibited content, and expected response; it does not invent a bounty promise.
- Status pages show affected components, user impact, update history, and resolution without sensitive internal detail.
- Public content, documentation, compatibility, policies, releases, and metadata are repository-versioned and schema-validated; a mutable runtime CMS is not authority.
- Current public content is indexable. Account, admin, preview scenarios, internal results, and obsolete content use explicit `noindex`/canonical policy.
- Home, Product, Documentation, and Release routes have content-specific social metadata images derived from approved assets and never include unproven performance claims.
- Publication fails closed when PT-BR or English copy, metadata, imagery, warnings, evidence, validation state, or review date is missing/stale.
- Release publication is atomic: manifest, notes, compatible docs, support matrix, artifacts, screenshots, channel metadata, and policy must agree.

## 17. Visual, Interaction, and Performance Acceptance

### Story catalog

Every shared component and composition requires stories for:

- default, hover, focus-visible, pressed, disabled, and loading;
- empty, error, warning, success, unavailable, stale, offline, and preview where applicable;
- PT-BR, English, and pseudo-locale;
- reduced motion and forced colors;
- 320px reflow, 390px mobile, 768px tablet, 960px desktop threshold, and 1440px wide;
- keyboard and screen-reader interaction.

### Screenshot matrix

Golden screenshots use deterministic data at:

- 1440×900;
- 1280×800;
- 960×900;
- 768×1024;
- 390×844;
- 320×800.

Capture W01–W18 on their required routes, PT-BR and English critical journeys, reduced-motion final frames, forced colors, and 400% zoom for representative complex routes. Timestamps, hashes, correlation IDs, and media crops are frozen. Baseline changes require a named design-contract reason and reviewer approval.

### Automated accessibility and interaction

- Zero serious or critical axe violations on every route/state.
- Keyboard-only E2E completes public search, documentation versioning, compatibility, release verification, account review/receipt, admin consent review, locale switch, and error recovery.
- No unnamed control, invalid ARIA relationship, focus trap, duplicate ID, hidden focus, or color-only status.
- Link/route tests prove every canonical route, breadcrumb, CTA, redirect, sitemap entry, and desktop contextual link.
- Production builds prove no fixture scenario switcher or fixture adapter is reachable.

### Performance

- Core Web Vitals targets at the 75th percentile: LCP ≤2.5s, INP ≤200ms, CLS ≤0.1.
- Public text, navigation, compatibility CTA, and critical notices render before heavy imagery.
- Fonts are self-hosted, subset for PT-BR/English, and use `font-display: swap`.
- Route-level bundle and image budgets are recorded in CI; a >10% regression requires explicit approval and evidence.
- Search/filter input remains responsive with the full deterministic content catalog.
- No autoplay media, blocking third-party script, or decorative canvas/WebGL dependency is permitted.

## 20. Executor Stop Conditions

Stop and return for design review if implementation would require:

- adding shadcn, a third-party registry, a dashboard template, or a stock marketing template;
- introducing an off-scale spacing value, fifth text size, third font weight, screen-local color, or radius above the two canonical values;
- publishing generated mockups as real product, editing values inside a real product capture, or dropping capture provenance;
- hiding simulated provenance, inventing a session/payment/device/admin effect, or making a preview look authoritative;
- exposing a self-signed/development installer or adding a “continue anyway” integrity bypass;
- merging public, account, and admin origins, shells, cookies, CSP, or sensitive state;
- replacing technical tables with generic card walls or requiring ordinary two-axis scrolling;
- removing documentation depth, evidence, risk, compatibility, recovery, or stale-version notices to fit a smaller viewport;
- clipping PT-BR/English critical copy or omitting a locale, metadata, screenshot, warning, or policy counterpart;
- weakening keyboard, focus, forced-colors, reduced-motion, 400% zoom, screen-reader, or contrast behavior;
- adding a claim without source, provenance, scope, version, validation state, and unproven boundary;
- shipping a route, link, menu, filter, form, confirmation, cancellation, or recovery path outside the canonical route/state contract.
